## Compared routes

`tools/pascal-compat/BOARDENT.PAS` executes the reconstructed Pascal `ElementDefs[E_BOARD_EDGE].TouchProc` after creating and saving a source board and four destination boards. It records four successful edge directions, a blocked destination that returns to the source board, and a destination that already contains the player.

The shared-engine side is `tools/runtime-compat/oop_movement.c::run_integrated_board_edge_actual_transition_checks`, compiled into `integrated_gameplay.wasm`. It uses the actual production `zoo_e_board_edge_touch`, `zoo_board_change`, `zoo_board_close`, `zoo_board_open`, `zoo_call_stack_tick`, `zoo_stat_move`, `zoo_board_draw_transition`, and `zoo_board_enter` implementations. The first touch queues the real production continuation; `zoo_call_stack_tick` resumes it as the game loop does. Board changes close and reopen serialized board records in the production `world.board_data[]` store.

## Controlled environment and limits

- The WASM fixture uses the same controlled bump allocator and `realloc` byte-copy behavior as the integrated replay runner. Allocation addresses are not compared; only engine state fields are.
- Video writes and sidebar updates use deterministic test callbacks. The production transition, board serialization, call-stack, and game-state routines run unchanged.
- The board payloads are serialized and reopened through LibZoo's in-memory `world.board_data[]` store. This probe does not exercise host filesystem access, loading a world from an external `.ZZT`, title selection, save/return, or other lifecycle routes.
- The older extracted-callback comparison remains as a separate boundary check under explicit `zoo_board_change` / `zoo_board_enter` service stubs. It is not used as evidence for the full-transition result here.
- No reconstructed Pascal gameplay source was modified for this probe. `BOARDENT.PAS` assigns a no-op video writer only to capture state without rendering.

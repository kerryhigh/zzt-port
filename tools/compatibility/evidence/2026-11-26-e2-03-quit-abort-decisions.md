# E2-03-AC001 — player abort and title quit decisions

**Result: D/DP passed for the frozen decision cases below.** E2-03-AC001 remains partial; this evidence does not close the full lifecycle transition matrix or add acceptance IDs.

## What was compared

`tools/pascal-compat/ABORTIN.PAS` compiles and runs the reconstructed Pascal routines directly. For player abort it calls the original `GamePromptEndPlay` with `Y`, `N`, and Escape while both paused and unpaused, then checks the existing no-prompt health-zero route. For title quit it calls the original `SidebarPromptYesNo('Quit ZZT? ', true)` and assigns its return value to `GameTitleExitRequested`, as `GameTitleLoop` does.

The production comparison in `tools/pascal-compat/compare-player-abort.js` consumes those captures and the runtime harness outputs from `tools/runtime-compat/oop_movement.c::run_integrated_end_play_checks` and `run_integrated_title_quit_checks`. The shared engine APIs are `zoo_game_resolve_end_play` and `zoo_game_resolve_title_quit` in `third_party/libzoo/src/libzoo/zoo_game.c`. Windows and Android keep their prompt/dialog handling in their frontends and call these shared state-resolution APIs.

The Pascal probe uses the existing deterministic `InputProbeSetReadKeys` hook at the input routine boundary. The original `GamePromptEndPlay` and `SidebarPromptYesNo` routines execute unchanged. Setup sets the player's health, pause flag, and active element for each row; it does not change reference gameplay source or prompt behavior. No clock, RNG, allocator, or hardware output is compared in these decision-only cases.

## Direct Pascal captures

`ABORT.OUT` columns are case, `GamePlayExitRequested`, `InputKeyPressed`, `GamePaused`, and health:

```text
1 1 0 0 37
2 0 0 0 37
3 0 0 0 37
4 1 0 1 37
5 0 0 1 37
6 0 0 1 37
7 1 0 0 0
```

Rows 1–6 are Yes/No/Escape at both pause states; row 7 is the health-zero no-prompt route. Yes accepts the exit, No and Escape reject it, and the previous pause state is retained.

`TQUIT.OUT` columns are case and `GameTitleExitRequested`:

```text
1 1
2 0
3 0
```

These are title quit Yes/No/Escape. Yes requests title exit; No and Escape leave the request clear.

The outputs were 83 bytes (`ABORT.OUT`, SHA-256 `B81BBC6D066E636BF3EEC8A236376CF2F7BF51C8AF94314716899B37A00E9511`) and 15 bytes (`TQUIT.OUT`, SHA-256 `183886D371228921F1F961DF371EE891D14EC00CC771F6F376D389964697AEA4`). They are transient files under `build/pascal-compat-verification/`, regenerated by the runner, and are not committed.

The output fixture uses `TQUIT.OUT` because DOS filenames are limited to 8.3 characters; the earlier overlong `TITLEQUIT.OUT` spelling was truncated by DOS and correctly failed the host-side capture check. The corrected filename passed the full clean run.

# Runtime compatibility checks

The player-input harness compares the production key queue against direct Turbo Pascal `InputUpdate` output for one-to-four-key bursts and a four-repeat burst, preserving the penultimate-byte copy quirk. It also checks queued arrow movement and CP437 bytes 0x82/0xFF.

The editor WASM harness extracts the exact editorFloodFill and editorCopyTile JNI functions plus the production placement, preparation, and paste helpers from app/src/main/cpp/native-lib.c. All four Pascal maps (bounded 3-by-3, 792-cell wrap, dense 17-by-17, and full 60-by-25) pass. EDPLACE.PAS matches pattern placement color, stat-0/player protection, plain clipboard tile paste, and MAX_STAT refusal. EDSTAT.PAS compares no-script paste and script-bearing Bomb copy/paste against Pascal, including stat fields, under-tiles, DataPos reset, and raw `B`, CR, NUL, `Z` bytes. It models Pascal's shallow `copiedStat := Board.Stats[statId]` pointer by changing the source script byte after copy, then checks the clipboard and pasted stat observe that byte. The production harness also checks that clearing the clipboard does not free or corrupt board-owned script data. Board draw/removal callbacks remain harness doubles; Android editor UI, device JNI execution, instrumentation, and device behavior remain open.

The game-start regression seeds a nonzero PIT elapsed time and centisecond counter before both title and play starts. A separate `game_clock.c` harness includes the production `zoo.c` elapsed-time helper, while `compare-game-clock.js` checks seven direct `SOUNDCLK.PAS` rows for threshold boundaries, immediate zero-duration success, minute rollover, retained counters, and modulo behavior. `ZEROSPD.PAS` runs the original `GamePlayLoop` for five zero-speed cycles; `compare-zero-speed-loop.js` matches the cycle count, phase, elapsed time, and counter against production `zoo_tick`. `GAMESCHD.PAS` then runs five original positive-speed cycles at TickSpeed 1/6/9, adds a five-PIT advance after the second clock poll in one case, and crosses the 59.80-second minute boundary in another. `compare-game-schedule.js` checks all five Pascal cycle timestamps and final tick counters against the production C tick loop; `verify.ps1` also pins the raw Pascal rows. The Android JNI frontend uses the same production helper in `app/src/main/cpp/zzt_frame_scheduler.h`; its deterministic runtime check covers 120 intervals at 60 Hz, a 300 ms catch-up, a >1 s timestamp rebase, timestamp rollback, and deadline changes for game cycles, next-frame results, modal prompts, and errors. A second runtime check drives the actual production `zoo_tick` through synthetic 60 Hz frames and compares its five speed-6 cycle timestamps with `GAMESCHD.PAS` in normal operation and after a 300 ms frame stall following the second game poll. The `TouchControlsInstrumentation` `frameLifecycleOnly` mode launches `MainActivity`, waits for a Choreographer callback to pass through `ZztNative.frame` and refresh UI status, confirms callbacks stop while paused, and confirms delivery resumes after resume.
